## Промт

Ты продолжаешь развитие проекта **«Экосистема цифровых сервисов 3DMP»**.

**Контекст и правила:**
- Язык общения и рассуждений — **только русский**.
- Проект — это **статические прототипы** (HTML + CSS + обычный JS, без сборки и фреймворков), данные в `localStorage`. Backend не подключён.
- Рабочая папка проекта — `project/` (эталон: единый каталог `project/assets/js/catalog.js`).
- Запуск: открыть `project/index.html` в браузере. Деплой: содержимое `project/` в папку `SAAS` → **https://sapfir.eu/SAAS/index.html**.
- **Границы:** НЕ трогать чужие проекты «Таблица заказов» (гравировка) и «Нормирование PRO» (`norms_*`), их таблицы/ключи/URL. Техническую часть (backend, БД, деплой) не реализовывать без явной просьбы.
- Сначала проверяй факты по файлам, потом вноси правки. Документы создавай только по просьбе.

**Что делать:**
1. Ознакомься с `RESUME.md` (полное описание, каталог, правила, changelog).
2. Внеси запрошенные изменения, сохраняя единую дизайн-систему (`project/assets/css/*`).
3. **При добавлении/изменении приложения сначала обновляй `catalog.js`** — хаб, гид, счётчики и P1 подхватят изменения. Для новых страниц подключай `assets/js/{catalog,store,auth,theme,guide}.js` перед `</body>` (по образцу существующих).
4. Соблюдай единые слои: `AppData` (профиль, заявки, команда, проблемы, журнал, настройки), `AppAuth` (роли), `theme.js` (тема), `guide.js` (гид).
5. После правок проверь целостность: баланс скобок в JS, совпадение `id` между HTML и JS, валидность ссылок в `catalog.js`, соответствие модулей P1 каталогу.
6. Для деплоя: указать, что залить, и напомнить поднять `?v=N` для сброса кэша.

**Формат ответа:** кратко и по делу, на русском; при изменениях — что сделано, результат проверок, что залить на сервер.

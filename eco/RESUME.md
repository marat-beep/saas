# 3DMP · Экосистема цифровых сервисов — резюме проекта

**Версия каталога:** 2.7 · **Обновлено:** 02.10.2026
**Формат:** статические прототипы (HTML + CSS + обычный JS, без сборки и фреймворков), данные в `localStorage`.
**Запуск локально:** открыть `project/index.html` в браузере.
**Деплой:** содержимое `project/` в папку `SAAS` на sapfir.eu → **https://sapfir.eu/SAAS/index.html** (со слэшем: `https://sapfir.eu/SAAS/`).

---

## 1. Что это

Единая экосистема для производственной компании «3Д Металлообработка Пресс» (штампы, пресс-формы, оснастка, ЧПУ, инжиниринг): клиентские сервисы, производственный контур, CRM/экономика, партнёрские кабинеты и облачная платформа (SaaS + маркетплейс + платежи).

**Итог:** 72 приложения (клиенты 14, сотрудники 39, партнёры 3, платформа 16), 56 модулей SaaS.
**Ориентация:** в первую очередь — **малые производственные предприятия** (мало людей, совмещение функций); крупным — модульность, feature flags и иерархия.

## 3. Единые слои и сквозные модули

- **`catalog.js`** — единый источник правды: группы, приложения, сценарии, легенда аудиторий, версия и changelog. Из него строятся хаб, гид, счётчики и модули P1.
- **`store.js` (`AppData`)** — данные поверх `localStorage`: `profile`, `requests` (сквозные заявки), `contacts`, `team`, `problems`, `log` (аудит), `settings`, `notifications`.
- **`auth.js` (`AppAuth`)** — роли: Все / Клиент / Сотрудник / Партнёр / Админ + **иерархия сотрудников** (директор → нач. цеха → мастер → оператор; инженер). Гейтинг групп, делегирование клиента (`canClientApp`) и доступ модулей по уровню сотрудника (`canStaffApp`).
- **Подразделения и иерархия (P13)** — цеха/участки/службы, сотрудники по уровням, орг-схема и матрица доступов по уровням.
- **`theme.js`** — светлая/тёмная тема (кнопка 🌙) и **масштаб шрифта** всей системы (функции `setFontScale/getFontScale`, кнопки A−/A+ в админке), `localStorage`, `data-theme` + класс `dark` + `color-scheme`.
- **Разделение предприятий** — в админке (P9 → «Организация») выбирается размер: малое / среднее / крупное; кнопка «Применить пресет» включает рекомендуемые модули через feature flags.
- **Адаптив** — компоненты подстраиваются под мобильный (<560), планшет (561–1024), большой экран (>1200).
- **`guide.js`** — гид по системе: плавающая кнопка ❓, поиск, переключатель темы; строится из каталога.
- **`export.js` (`AppExport`)** — единый движок выгрузок: `csv/json/ics/tableHtml`, `docBody/exportDoc` (Word), `exportPdf` (печать), `reportDocument` — конструктор отчёта с шапкой/брендом, KPI, секциями и подписями. Используется центром экспорта (P15) и может подключаться любым модулем.
- **`utils.js`** — форматирование, `Store`, номера, toast. **`router.js`** — переключение экранов.

## 5. Дизайн-система

- **Токены** (`tokens.css`): цвета, типографика, отступы, тени; темы по аудиториям (`data-audience`: clients/staff/partners/platform/marketplace); тёмная тема (`html[data-theme="dark"], html.dark`).
- **Компоненты** (`components.css`): оболочка приложения/веб, шапка, карточки, чипы, формы (в т.ч. кастомный `select`), кнопки, бейджи, трекеры, прогресс, выноски. Мобильные правки.
- Каждое приложение — `.app-shell` (мобильный фрейм) или `.web-body` (широкая консоль).

## 6. Сквозные сценарии

- Кооперация заводов: M1 → B9 → B10 → B3 → P5.

## 7. Как добавить приложение

1. Создать папку `apps/<id-app>/` с `index.html` и `<app>.js` (по образцу).
2. Подключить перед `</body>`: `assets/js/toolkit`-скрипты через `../../assets/js/{utils,router,catalog,store,auth,theme,guide}.js`.
3. Добавить запись в `catalog.js` (id, icon, title, desc, href).
4. При необходимости добавить модуль в `apps/p1-cloud/p1.js` (`MODULES` и группировка).
5. Проверить целостность (см. раздел 8).

## 8. Проверка целостности

- Баланс скобок `{} () []` во всех JS.
- Совпадение `id` (селекторы `$('#id')` в JS ↔ `id="..."` в HTML).
- Валидность всех `href` в `catalog.js`.
- Соответствие модулей P1 (не платформенные приложения) каталогу.
- Отсутствие дублей ID.

## 9. Ограничения и границы

- **Не трогать чужие проекты:** «Таблица заказов» (гравировка) и «Нормирование PRO» (`norms_*`), схему/ключи/URL Supabase.
- Backend, БД, деплой-инфраструктуру не реализовывать без явной просьбы — фокус на продукте и прототипах.
- Данные — демонстрационные; кнопка «Сбросить демо-данные» очищает состояние.

## 11. Оценка применимости и иерархии

- **Малые предприятия (до ~30–50 чел.):** система применяется как есть — роли «Все/Клиент/Сотрудник/Партнёр/Админ» + делегирование функций достаточны; подходят клиентские сервисы и базовый производственный контур (B1/B10/B11/B3).
- **Тяжёлые заводы со сложной структурой (цеха, участки, службы, несколько юрлиц):** полезна **дополнительная иерархия** — уровни *директор → начальник цеха → мастер → оператор*, привязка к **подразделениям/цехам** и **мультизавод/tenant**. Сейчас это частично закрыто (самостоятельные дашборды B23, уровни в B7, роли P8, тенанты P1), но рекомендуется добавить:
  1. справочник подразделений и привязку ролей/пользователей к ним;
  2. иерархические роли (директор/начальник цеха/мастер/оператор) с наследованием прав;
  3. фильтрацию данных по подразделению/цеху во всех модулях (объекты → цех);
  4. агрегирующие дашборды по уровням и «сводку по заводу/холдингу»;
  5. мультизаводскую модель (несколько заводов в одном тенанте).
- Вывод: для **малых** — разделение по иерархии не обязательно; для **крупных** — обязательно, поверх существующей модели ролей и делегирования.

# Интеграция «Нормирование PRO» в экосистему 3DMP (SaaS)

**Цель:** сделать «Нормирование PRO» частью экосистемы 3DMP как **продукт SaaS** (тенант-модуль), перенеся логику, справочники и сценарии в единую дизайн-систему и мультитенантную модель.

> Важно (границы): **не трогаем** исходный проект — его `norms_*` таблицы, Supabase-ключ `ljjuaxbqmcmocvcccfyx`, FTP, файлы `norms-*.js` и `norms.html`. Мы **переосмысливаем** функциональность в экосистеме 3DMP (shema `eco`/отдельный проект Supabase) и не копируем чужие секреты/ключи.

- ERP-SPA на чистом JS (ES-модули), 26 файлов `norms-*.js`, 17 вкладок, стек: Vanilla JS + **Supabase (PostgreSQL)** + HTML/CSS, без фреймворков.

- Известные пробелы исходника: пароли plain-text, вложения не используются, монолит `norms.html`.

## 3. Модель SaaS (адаптация)

- **Продукт «Нормирование PRO»** в каталоге экосистемы (P14) — консоль продукта, внутри которой сгруппированы все модули нормирования; продаётся тенантам как набор модулей в P1 Cloud.
- **Тенанты и мультизавод:** у каждого завода — свой тенант, состав модулей и тариф (P1). White-label (P6), биллинг (P5).
- **Роли:** platform-admin (оператор SaaS) → tenant-admin (директор завода) → подразделения/уровни (P13) → сотрудники. Делегирование функций (A14) для клиентской части.
- **Данные:** схема `eco_*` в отдельном проекте Supabase (не `norms_*`), RLS по `auth.uid()` и `tenant_id`; Storage для вложений; API слоя (P4) для 1С/ERP.

- **Формулы и K-коэффициенты** (norms-constants/norms-calc): норма = база × K_материала × K_точности × K_геометрии × K_оснастки (+ серийность) → уже в B8/B26; дополнить наборами K.

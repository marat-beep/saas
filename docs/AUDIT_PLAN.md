# Программа аудита 3DMP Service — план

> Режим: непрерывный аудит. Главный выход — живой **«План обновления»** (`docs/UPDATE_PLAN.md`), который пересобирается при каждом прогоне. Источник правды по работам — `docs/BACKLOG.md` (§3 синхронизируется генератором). Версия методологии: 1.0.

## 1. Цель и рамки
**Цель:** независимо и воспроизводимо оценить сервис (архитектура → функции → логика → применимость), получить измеримые оценки и непрерывно формируемый план обновления.

**Рамки:** проект `SAAS/` (приложения `apps/`, `assets/`, `eco/`, `index.html`, `supabase/`), бэкенд Supabase `zfkbzzmtbrueaksfaqbf`, деплой `sapfir.eu/saas/`. **Не трогаем:** `НОРМ_РАЗРАБ/`, чужие проекты (`gravirovka`, `norms_*`), схемы/ключи вне `SAAS`.

**Принципы:** воспроизводимость, доказательность (файл/строка/артефакт), приоритизация (Impact × Severity × Вес / Effort), трассируемость (ТЗ ↔ каталог ↔ модуль ↔ RPC ↔ UI ↔ тест), регулярность (CI), без изменения данных на этапе аудита.

## 3. Уровни проверки (гейты)
- **L0 авто-статик** — `tools/audit.ps1` + `tools/audit-deep.ps1`.
- **L1 авто-БД** — `tools/db-smoke.ps1` + `tools/db-integrity.ps1`.
- **L2 авто-трассировка** — `tools/trace-matrix.ps1` (catalog↔apps↔RPC↔UI).
- **L3 сценарии** — ручные чек-листы (`AUDIT_CHECKLIST.md`): золотые пути, негатив, роли, моб./офлайн.
- **L4 применимость** — интервью/наблюдение/SUS/пилот (производство/организация/люди).

Гейт релиза: L0–L2 зелёные, нет Blocker/Critical, Major ≤ порога, кодировка=0, перегрузок 0.

## 6. Роли (RACI)
- **Владелец аудита** (ведущий): методология, прогоны, отчёт.
- **Владелец продукта**: приоритеты, утверждение волн плана.
- **Админ платформы**: БД/RLS/безопасность, бэкапы.
- **Разработка/QA**: исправления, регрессионные тесты.
- **Пользователи (цех/офис)**: L4-оценка применимости.

## 7. Критерии завершённости аудита (DoD)
Повторный прогон даёт стабильный результат; план генерируется автоматически и меняется при новых находках; гейт релиза описан и проверяется; артефакты в репозитории; локальный и CI-запуск воспроизводимы.

## 8. Безопасность аудита
Только чтение; секреты не логируются/не коммитятся; управляющие операции (миграции/деплой) — вне аудита, по стандартной процедуре; пилотные опросы — анонимно.

# L4 — Оценка применимости (3DMP Service)

Уровень L4 оценивает не код, а **применимость** сервиса: на производстве, в организации и для людей. Формализует интервью, наблюдение и опросы; результаты (находки `D*`) вносятся в `audit/findings.json` вручную (метод `user`).

## 1. Методы
- **Наблюдение** за работой (цех/офис): какие экраны, где Excel/бумага, где трение.
- **Сценарные задачи** (task-based): измерить успех и время.
- **SUS** (System Usability Scale, 10 вопросов, шкала 1–5), цель ≥ 68.
- **NASA-TLX** (опц.): нагрузка по задачам.
- **Интервью** по ролям (мастер, технолог, ОТК, снабжение, экономист, менеджер, администратор).

## 2. Роли для выборки
| Роль | Профиль | Ключевые задачи |
|---|---|---|
| Мастер/оператор | цех | терминал: запуск/пауза/завершение, офлайн |
| Технолог | КТПП | маршрут/УП, нормы |
| ОТК | качество | проверки, измерения, паспорт/QR |
| Снабжение | закупки | тендер, поставщики, приёмка |
| Экономист | экономика | себестоимость, бюджеты, отчёты |
| Менеджер | продажи | заявка→КП→счёт |
| Админ (орг./SaaS) | админ | пользователи/роли, безопасность, интеграции |

Выборка пилота: 8–12 человек (по 1–2 на роль), 1 подразделение.

## 3. Сценарные задачи (фиксируйте: успех да/нет, время, ошибки, комментарий)
| ID | Задача | Роль | Целевое время |
|---|---|---|---|
| T-01 | Создать заявку и добавить позиции | менеджер | ≤ 3 мин |
| T-02 | Запустить наряд и операцию в терминале (в т.ч. офлайн) | мастер | ≤ 2 мин |
| T-03 | Внести измерение ОТК с телефона | ОТК | ≤ 1 мин |
| T-04 | Оформить паспорт и открыть QR | ОТК | ≤ 2 мин |
| T-05 | Принять материал на склад (партия/адрес) | снабжение | ≤ 2 мин |
| T-06 | Создать документ ЭДО и выдать поручение | менеджер | ≤ 3 мин |
| T-07 | Построить отчёт по модулю и выгрузить XLS | экономист | ≤ 3 мин |
| T-08 | Добавить пользователя и роль | админ | ≤ 3 мин |
| T-09 | Настроить 2FA и посмотреть «мои устройства» | админ | ≤ 3 мин |
| T-10 | Установить расширение и включить коннектор | админ SaaS | ≤ 3 мин |

## 4. Опросник SUS (1 — полностью не согласен … 5 — полностью согласен)
1. Я хотел бы часто пользоваться этой системой.
2. Система излишне сложна.
3. Система кажется простой.
4. Мне нужна помощь технического специалиста, чтобы пользоваться системой.
5. Различные функции хорошо интегрированы.
6. В системе слишком много несогласованности.
7. Большинство людей быстро освоят систему.
8. Система очень неудобна в использовании.
9. Я уверенно пользовался системой.
10. Мне нужно многое изучить перед началом работы.

**Расчёт SUS:** для нечётных `(ответ−1)`, для чётных `(5−ответ)`; сумма ×2.5 → 0–100. Цель ≥ 68.

## 5. Гид наблюдения (чек-лист)
- Где пользователь переключается в Excel/бумагу/телефон?
- Сколько кликов до ключевой операции? Есть ли лишние шаги?
- Что непонятно без объяснения (подписи/поля/статусы)?
- Мобильный: удобны ли тач-цели, офлайн, скан/фото?
- Ошибки: понятны ли сообщения, легко ли исправить?

## 6. План пилота
1. Согласовать роли/задачи, договориться о времени (2–3 часа).
2. Провести наблюдение + задачи T-01…T-10, зафиксировать метрики.
3. Заполнить SUS (анонимно), собрать 3–5 ключевых «болей».
4. Оформить находки `D*` (severity Major/Minor) с доказательством (цитата/метрика).
5. Внести в `audit/findings.json` (метод `user`), перегенерировать `UPDATE_PLAN.md`.

## 7. Шаблон находки L4
```
{ "area":"D", "sev":"Major|Minor", "title":"...", "detail":"цитата/метрика", "evidence":"роль/задача/время", "method":"user", "effort":3, "impact":3, "status":"open" }
```

## 8. Критерии применимости (DoD L4)
- SUS ≥ 68; task-success ≥ 90%; ключевые задачи в целевом времени.
- Нет блокирующих «болей» (P0/P1) в ключевых сценариях.
- Найдено и внесено ≥ 5 улучшений (или подтверждено отсутствие).

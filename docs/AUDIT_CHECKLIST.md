# Чек-листы аудита (3DMP Service)

Отмечайте результат: `pass | fail | n/a`, при `fail` — находка в `audit/findings.json` с ID ниже.

## L3 — сквозные сценарии (C, B, D, G)
| ID | Проверка | Критерий pass |
|---|---|---|
| C-01 | Заявка → КП → договор → счёт → оплата | сущности связаны, статусы переходятся, данные не теряются |
| C-02 | Потребность → закупка/тендер → поставщик → приёмка → склад | приёмка создаёт партию/остаток, минимум контролируется |
| C-03 | Заказ → маршрут/УП → наряд → MES/терминал → ОТК → паспорт | факт часов/операции корректны, себестоимость считается |
| C-04 | ТОиР: заявка → наряд → предиктив → закрытие | риск/наработка отображаются |
| C-05 | ЭДО: создание → регистрация → поручение → выполнение → архив | поручение выдаётся выбранному исполнителю, приходит уведомление |
| C-06 | Админ: пользователь/роль → модуль → политика → журнал | права применяются, доступ в журнале |
| C-07 | Расширение: каталог → установка → включение (connector→интеграция) | зависимости проверяются, точка интеграции создаётся |
| C-08 | Мониторинг: `health_scan` → алерт → уведомление → закрытие | алерт дедуплицируется, закрывается при норме |
| R-01 | Роли: скрытие модулей/кнопок (`roles`,`data-cap`,`CAPS`) | недоступное не показывается и не выполняется |
| G-01 | Мобильный режим и офлайн (терминал/ОТК/склад) | действия доступны, офлайн-очередь отправляется без дублей |

## L4 — применимость
### D1. Производство (цех/планирование/ОТК/ТОиР)
| ID | Проверка | Критерий pass |
|---|---|---|
| D1-01 | Соответствие реальным операциям цеха | мастера работают без обходных Excel |
| D1-02 | Терминал оператора (запуск/пауза/завершение) | понятен оператору, офлайн |
| D1-03 | Планирование (Гантт/APS) | план применим к загрузке центров |
| D1-04 | ОТК/SPC | измерения вносятся с телефона, сигналы информативны |

### D2. Организация
| ID | Проверка | Критерий pass |
|---|---|---|
| D2-01 | Роли/регламенты соответствуют оргструктуре | нет «лишних» прав |
| D2-02 | Тарифы/модули/бренд управляемы | настройка без разработчика |
| D2-03 | Отчётность для руководства | KPI/дашборды достаточны |

> Детальные инструменты L4 (SUS, задачи T-01…T-10, наблюдение, пилот) — `docs/AUDIT_L4_APPLICABILITY.md`.

### D3. Люди (UX)
| ID | Проверка | Критерий pass |
|---|---|---|
| D3-01 | SUS-опрос (пилот) | ≥ 68 |
| D3-02 | time-on-task ключевых операций | ≤ целевого |
| D3-03 | Обучение/справка | новый сотрудник справляется по гиду |

## L0–L2 (авто, отмечаются инструментами)
`A-*` архитектура, `B-*` полнота, `E-*` данные, `F-*` безопасность, `H-*` производительность, `I-*` эксплуатация, `J-*` документация, `K-*` интеграции — формируются скриптами `tools/audit-*.ps1`, `trace-matrix.ps1`, `db-integrity.ps1`, `security-check.ps1`.

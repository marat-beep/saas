# План обновления v2 — «Цифровой контур предприятия» (W13–W27)

Единый план развития 3DMP Service на базе анализа решений лидеров рынка и функциональной карты **1С:ERP**.
Источники анализа: **intechnology.ru (ZIFRA, «Диспетчер»)** — MDC/MES/EAM/УП; **bitrix24.ru** — совместная работа/CRM/задачи/автоматизация/ИИ; **elma365.com** — low-code BPM/CSP/КЭДО/ESM; **tools.spectr-ait.ru (СПЕКТР)** — инструментальное хозяйство; **solutions.1c.ru/erp** — комплексное управление (ERP, MDM, CRM, HRM, FRP, SFM/WMS/TMS, PDM/PLM, ITSM, EAM/CMM, PMO/EPM, e-Learning, бух/налог, Документооборот, EHS).

## 0. Принципы и рамки
- Стек без изменений: vanilla HTML/CSS/JS + Supabase (Postgres + RPC + RLS), PWA-офлайн, очередь обмена `app_integrations`.
- Каждая волна — миграция `0158+` (идемпотентная), RPC, UI-модули, KB-статья, `apply_all.sql`, `?v=N`, смоук. Внешние системы (LLM/CV/ЭДО-оператор/ЭП/PLM) — через очередь интеграций (как в W6/W9/W11).
- Максимальное **переиспользование**: `shell.js`, `AppAPI`, `export.js`, `module-report.js`, `data-cap`+наборы прав, согласования (W10), уведомления, `app_knowledge`, `app_files/attachments`, `labels`, WMS-адреса (W3), `app_integrations` (W6).
- Итог плана — 15 волн, миграции `0158…0174`. Реализация волнами по подтверждению.

## W13. Инструментальное хозяйство 2.0 (`0158`) — приоритет высокий
**Цель:** поэкземплярный учёт инструмента/оснастки, каталог, поверка СИ — по мотивам СПЕКТР.
- T1 Поэкземплярный учёт: `app_tool_items` (serial, tool_id, location_id, status on_stock/issued/on_machine/worn/scrapped, resource_min, used_min, владелец-наряд/станок), история операций; RPC `app_tool_item_list/save/move`, `app_tool_issue`, `app_tool_return`, `app_tool_install`.
- T2 Адресное хранение + маркировка: связь с `app_wh_addresses`, генерация QR/ШК через `apps/labels`; инвентаризация (`app_tool_inventory_*`).
- T3 Цифровой каталог: `app_tool_catalog` (производитель, геометрия, тип обработки, материал, аналоги, совместимость), параметрический поиск.
- T4 Подбор по техкартам: связь `app_route_steps`/BOM → инструментальные сборки, ведомость оснащения.
- T5 Поверка СИ: `app_meas_instruments` + поверка/калибровка, напоминания, блокировка выдачи непроверенного.
- UI: расширить `apps/tooling` (+киоск-режим), `apps/labels`.
- **DoD:** жизненный цикл каждого экземпляра; выдача/возврат; каталог и аналоги; СИ с поверкой; инвентаризация.
- Оценка: **L**. Зависимости: W3 (WMS), M7 tooling.

## W14. CMMS/EAM 2.0 (`0159`) — приоритет высокий
**Цель:** предиктив и энерго/дисциплина/УП/3D/холдинг — по мотивам «Диспетчер».
- E1 Вибродиагностика/предиктив: `app_vibro_readings`, правила порогов, прогноз, авто-заявка ТОиР; связь IIoT.
- E2 Энергоменеджмент: `app_energy_readings` (эл./газ/вода/воздух), удельное потребление, KPI/цели.
- E3 Простои/дисциплина: `app_downtime_reasons` (классификатор), `app_operator_log` (вход/выход RFID/ШК), статистика.
- E4 Версии УП (CNCLAN): `app_nc_versions` (эталон/сравнение/автопередача/оповещение о расхождении).
- E5 3D-визуализация: `app_layouts` (позиции станков) + SVG-карта статусов/загрузки.
- E6 АРМ Холдинг: агрегация KPI площадок (задел для W22).
- UI: расширить `apps/maintenance`, `apps/oee`, `apps/iiot`, `apps/nc`, `apps/energy` (нов.).
- **DoD:** авто-наряд по вибрации; энергоKPI; причины простоев и время оператора; сверка УП с эталоном; карта цеха.
- Оценка: **L**. Зависимости: W9 (IIoT/OEE/APS), M1 (ТОиР/ЧПУ).

## W15. Low-code workflow (`0160`) — приоритет высокий
**Цель:** конструктор процессов/правил/форм поверх согласований W10 — по мотивам ELMA365.
- L1 Конструктор процессов: `app_process_defs` (этапы, формы, условия, SLA, роботы), движок `app_process_instances` + задачи этапов; согласования W10 как частный случай.
- L2 Роботы/триггеры: `app_rules` (when/if/then) над событиями (создано/статус/срок/поле).
- L3 Конструктор карточек/форм: `app_form_defs` (кастомные поля/формы на модуль без миграций).
- UI: `apps/builder` (расширить), `apps/access` (этапы).
- **DoD:** настраиваемый процесс без кода; правила срабатывают; свои поля.
- Оценка: **L**. Зависимости: W10.

## W16. Совместная работа (`0161`) — приоритет средний
**Цель:** задачи/проекты, обсуждения, БЗ 2.0, контакт-центр — по мотивам Bitrix24.
- C1 Задачи/проекты: `app_tasks`, `app_projects` (канбан/Гант/чек-листы, учёт времени), связь заявки/наряды; модуль `tasks`.
- C2 Обсуждения/чат: `app_messages` (комментарии/упоминания, ссылка на объект).
- C3 БЗ 2.0 + профиль: разделы/версии/поиск (расширить `app_knowledge`), профиль сотрудника.
- C4 Контакт-центр: единый inbox (письма/чаты/SMS → лид/сделка), шаблоны, AI-скоринг разговора (задел).
- UI: `apps/tasks` (нов.), расширить `apps/crm`, `apps/guide`, `apps/staff`.
- **DoD:** доски задач; обсуждения у объектов; структурированная БЗ; омниканальный inbox.
- Оценка: **M**. Зависимости: R1 (CRM), P5 (интеграции).

## W17. Экосистема и интеграции (`0162`) — приоритет средний
**Цель:** открытая платформа — по мотивам Bitrix/ELMA/1С.
- X1 Публичный REST API + webhooks + кабинет разработчика: ключи, лимиты, журнал (расширить `apps/api`).
- X2 1С/ERP-коннектор углублённо: заказы/склад/счета + **МДМ-сопоставление номенклатуры**.
- X3 PLM/техподготовка: импорт техпроцессов/инструмента (NX/Teamcenter/«Полином»/«Вертикаль»).
- X4 Проверка контрагентов (Спарк-подобно): внешний сервис + скоринг риска в карточке.
- X5 Электронная подпись + OCR: `app_signatures`, распознавание сканов → документы (задел под W19/W20).
- X6 Реестр решений (marketplace): установка расширений/шаблонов флагами (расширить `apps/marketplace`).
- X7 Охрана труда — вынести в W21 (отдельная волна).
- **DoD:** внешние интеграции по ключам; обмен с 1С/PLM; риск-балл контрагента; подпись/OCR.
- Оценка: **L**. Зависимости: P5, W19/W20.

## W18a. Финансы и управленческий учёт (`0163`) — приоритет высокий

- **DoD:** бюджеты и план-факт; платёжный календарь; себестоимость по факту.
- Оценка: **L**. Зависимости: M6 (финансы), экономика.

## W18b. НСИ / MDM (`0164`) — приоритет высокий

- Оценка: **M**. Зависимости: W17 (X2/X3).

## W19. ЭДО / СЭД (`0166`) — приоритет высокий (по запросу)
**Цель:** электронный документооборот — по мотивам 1С:Документооборот и ELMA CSP.
- `app_doc_flows` (входящие/исходящие/внутренние/организационно-распорядительные), `app_doc_types`, `app_doc_nomenclature` (номенклатура дел/архив), регистрация и нумерация, резолюции/поручения, `app_doc_links` (связь с заявкой/договором/счётом/контрагентом).
- Маршруты согласования — reuse W10 (`app_approval_*`) + конструктор W15; версии и листы согласования; шаблоны (`apps/templates`/`docbuilder`).
- Вложения/сканы + OCR (W17/X5); электронная подпись; журналы и аудит (W10).
- RPC: реестр документов, регистрация, отправка/получение, резолюции, архив, поиск, сроки/контроль исполнения.
- UI: новый `apps/edo` (расширить `apps/docs`).
- Интеграции: ЭДО-операторы (Диадок/СБИС) и e-mail — через очередь.
- **DoD:** регистрация и маршруты документов; связь с бизнес-объектами; архив/номенклатура дел; подпись/OCR (задел).
- Оценка: **L**. Зависимости: W10, W15, `app_files`.

## W20. КЭДО (`0167`) — приоритет высокий (по запросу)
**Цель:** кадровый электронный документооборот — по мотивам 1С:ЗУП и ELMA365 КЭДО.
- `app_hr_docs` (виды: приказ о приёме/переводе/увольнении, заявление на отпуск, больничный, ознакомление), `app_hr_doc_templates`, `app_hr_requests` (заявления сотрудника из ЛК), Маршруты и ознакомление, `app_hr_sign` (ПЭП/УНЭП/УКЭП/Госключ — задел через интеграции), `app_mchd` (машиночитаемые доверенности).
- Личный кабинет сотрудника: заявления, ознакомления, свои документы, уведомления; журналы и аудит (W10).
- RPC: реестр кадровых документов, создание по шаблону, подписание/ознакомление, ЛК, МЧД, сроки хранения.
- UI: новый `apps/kedo`; интеграция с `apps/hr`/`apps/staff`.
- **DoD:** кадровые документы по шаблонам; электронное подписание/ознакомление; ЛК сотрудника; МЧД (задел).
- Оценка: **L**. Зависимости: W19 (ЭДО-механику переиспользуем), W16 (ЛК/уведомления), hr/staff.
